# Передача MiroFish Ops другому человеку

Этот пакет самодостаточен: в нём нет ни одного ключа, пароля или адреса сервера,
которые нельзя показывать. Новый владелец разворачивает всё на своей машине и со
своими доступами — ничего из ваших передавать не нужно и нельзя.

## Что отдать

Папку `projects/mirofish-ops` целиком — семь файлов:

| файл | что делает |
|---|---|
| `install-mirofish.sh` | ставит движок: пользователь, свой Node и Python, uv, клон форка, claude CLI |
| `deploy-web.sh` | выкатывает интерфейс, nginx, пароль на вход, накладывает патчи |
| `web.py` | сам интерфейс: форма, очередь, страница прогона, PDF |
| `ingest.py` | приём материала: текст, ссылка, файлы, картинки креативов |
| `scene.py` | зал с персонажами и раскладом позиций |
| `translate.py` | переводы заключения на русский и казахский |
| `patches/` | врезки в движок: OpenRouter, синтетическая аудитория, «говорят почти все» |
| `assets/` | логотип и иконка |

Сам движок (`amadad/mirofish`) в пакет не входит — установочный скрипт клонирует
его с GitHub. Это чужой код под AGPL-3.0.

## Чего НЕ передавать никогда

- `/opt/mirofish/.env` с сервера — там ключ OpenRouter.
- `/opt/mirofish/.claude/` — авторизация вашей подписки Claude. Новый владелец
  входит своей, одной командой.
- SSH-ключи и пароль basic-auth от вашей установки.
- Файлы прогонов `uploads/runs/` — там ваши материалы и отчёты.

Ничего из этого в пакете нет, но на сервере есть — поэтому отдавайте папку
из репозитория, а не копию каталога с машины.

## Что новому владельцу понадобится своё

1. **Сервер** — Ubuntu, 4 ГБ памяти, 20 ГБ свободного диска. Подойдёт любой VPS.
2. **Подписка Claude** (бесплатный режим) — вход в браузере при установке.
3. **Ключ OpenRouter** (платный режим, по желанию) — `openrouter.ai`, депозит
   от $10. Без ключа работает только режим подписки.

## Порядок установки у него

```bash
# 1. скопировать файлы пакета в /tmp на свой сервер
scp -r mirofish-ops/* ubuntu@СВОЙ_СЕРВЕР:/tmp/
ssh ubuntu@СВОЙ_СЕРВЕР

# 2. движок
bash /tmp/install-mirofish.sh

# 3. вход в подписку — интерактивно, нужен браузер
sudo -u mirofish -H env PATH=/opt/mirofish/node/bin:/usr/bin:/bin \
  HOME=/opt/mirofish /opt/mirofish/node/bin/claude
#    внутри: /login → открыть ссылку → вставить код → /exit

# 4. интерфейс (напечатает логин и пароль — записать)
mkdir -p /tmp/patches /tmp/assets && cp /tmp/patches/* /tmp/assets/* 2>/dev/null
bash /tmp/deploy-web.sh

# 5. по желанию — платный режим
sudo sed -i 's|^OPENROUTER_API_KEY=.*|OPENROUTER_API_KEY=ЕГО_КЛЮЧ|' /opt/mirofish/.env
sudo systemctl restart mirofish-web
```

`deploy-web.sh` рассчитан на nginx с сайтом, где есть `server_name <домен>` и
`listen 443`. Если конфигурация другая — сниппет `/etc/nginx/snippets/mirofish.conf`
подключается вручную, скрипт об этом скажет.

## Что сказать про лицензию

Движок распространяется под **AGPL-3.0**. Для внутреннего использования ограничений
нет. Если новый владелец поднимет из него **публичный сервис**, он обязан раскрыть
свои модификации — включая патчи из `patches/`. Поэтому держать установку за
авторизацией, как это сделано здесь, — не только вопрос расходов.

## Что он получит

Интерфейс на своём домене: форма приёма материала (текст, ссылка, файлы,
картинки), выбор размера и состава аудитории (пол, возраст, уточнение),
выбор движка (подписка или смесь из четырёх моделей), очередь на одну симуляцию,
живой зал с персонажами по ходу прогона, расклад позиций, выгрузка в PDF,
переводы заключения и повторный запуск с теми же настройками.
